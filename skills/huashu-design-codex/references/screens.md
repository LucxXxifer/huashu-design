# 頁面、App 與靜態圖

**Web／Dashboard。** 主角應是可見的事實或產品正在工作的畫面。依既有 codebase、元件、字體和資訊層級創作；沿用 HTML、React、CSS 或其他原生工具。用 [web](runtime.md#web) 驗 1440 與 375 寬度，覆蓋關鍵操作、錯誤／空／載入／成功狀態、鍵盤與滾動。初稿也要真的試用。模型看完長截圖再看原尺寸的局部；背景圖、透明或混色文字需人工核對對比，不能只看 lint。需要 Tweaks 時共用一份 state/store，再寫 localStorage；測同頁更新、重新整理保存和重置，不讓控制器與畫面各持獨立 state。

**App。** 從真產品畫面或經核實的內容出發，按題材選八種範式之一：介面是場景、簽名物件、時間有形狀、語義色、內容當主角、AI 在物上、角色承載狀態、可達性定形式。參考上游 App paradigm，真實套用主操作、返回、長頁、輸入、空狀態、安全區和裝置比例。網頁 shell 是原型，不叫原生 App。若無真截圖，要說明採用可操作的重建畫面或還缺素材。

**資訊圖／長圖。** 先定數據的關係（時序、比較、空間或拓撲），選相符的幾何；核對數值、基準、單位與註釋。小紅書用跨片的節奏和連續長圖，標註預計切線、邊距、字級和每圖意義；按給定規格渲染，再用 [images](runtime.md#images) 驗整數像素和無缺行接縫，觀看每片避免切字。上游 sticker 有獨立授權，選用前先讀授權。

**App Store。** 先查要交的商店、裝置、區域與當日規格；從真 App 截圖選主畫面。宣傳標題應由畫面支撐，保留銜接與明確順序，查裝置框、安全區、字級、像素及透明度。用 `images` 驗批次尺寸、張數與 alpha；仿商店樣圖或無真 App 都標清楚，不能表示已通過提交審查。

# 方向與評審

在同一份紀錄寫 brief、現有資產、六張卡、三稿、方向停點、打磨與驗收。事實多時用 `product-facts.md`，具名品牌用 `brand-spec.md`。複用舊專案的設計語言；新媒介的獨立交付若未有適用的選稿，仍須另選方向，例如原型已選 A 不等於整套 App Store 圖已選 A。

每張卡用五欄：**來源／看過的畫面**（含日期、URL 或固定路徑）；**form 五問**；**主角素材**；**借用的結構**（可用原尺寸與主要區塊比例）；**自己的語言**（字形、配色、構圖、狀態）。設計師卡找實際作品；同媒介卡看原圖或網頁截圖；風格卡從有對應媒介的樣張隨機抽兩張，記候選清單和結果。抽到與受眾衝突的樣張可另抽並記理由。六卡是決策資料，三個真稿才是使用者拿來比較的東西。

| 媒介 | 每個方向的代表稿 |
|---|---|
| 網頁／資訊圖／原型 | 一個完整可打開的 HTML（或該專案原生預覽）與真截圖 |
| Deck | 兩頁具代表性且內容不同的真頁，附全稿預計節奏 |
| 影片 | 真實渲染的關鍵幀板、配色、定位、參照；需能看見主角與構圖 |
| 封面／單圖 | 一張真圖 |
| 小紅書長圖 | 封面與一張內頁 |
| 商店圖 | 前三張實際編排的圖 |

比較前逐稿看圖並改一次，檢視三稿是否連資訊順序、敘事或互動骨架都不同。和參照並排看：如果看成同一作品的新版，換掉表達語言；保留有效的節奏或資訊結構。其他三個方向用一句話說明。先展示，再等選擇。無互動環境將狀態記為 `awaiting direction`；不用自己選，也不生成正式稿。「我選 B，保留 A 的字級」是有效選擇；保留原話及稿件版本，沒有必要在明確語義下強迫使用者重複固定句型。

正式稿兩輪從全畫面走查開始。一輪先看主語與版式、情報順序、內容和功能，另一輪看閱讀距離、字重、邊緣、安全區、動態與畫質；每輪寫「哪張圖、哪個問題、怎麼改、改完看哪張」。技術錯誤與主觀建議分開；評審給截圖／頁號／時間點、嚴重度與最小修法，避免用總分代替判斷。模型可做內部視覺審閱，真人是否選稿和認可作品另記。

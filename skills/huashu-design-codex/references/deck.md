# Deck：HTML、PDF 和 PPTX

用每頁一個洞見、主角和敘事角色控制節奏。上游可沿用 `assets/deck_stage.js`／`deck_index.html` 做瀏覽外殼；匯出時每個 entry 是一頁，舞台固定比例，不把導覽、控制列或超出裁切的內容當簡報。先搭封面和關鍵頁，三個方向各做兩頁。PDF 是原版預設成品；使用者指定交付格式時照做。

1. 每頁留一份**可見關鍵文字**和應有的圖片／原生元件清單；較長 deck 用 index 把頁序、標題與路徑列好。檢查舞台尺寸、文字裁切和字型。正文大小依觀看距離決定；請先以實際放映大小看字，不能用 6px 的最小輸入值當建議字級。
2. [deck](runtime.md#deck) 用 Chrome 生成單頁 PDF 後合併，重開驗頁數並逐頁抽取文字。同時保留每頁截圖。原 PDF、逐頁 render 和文字檢查彼此獨立；對圖表數值、圖片裁切和列印特效仍要目視。HTML 任一頁壞掉不發缺頁 PDF／PPTX。
3. 要可編輯：用同一份內容／幾何資料出明確的 native manifest，或用簡報原生作者工具。這個 adapter 做文字、矩形、橢圓和圖片；它不會把任意 CSS、圖表、影片、字型或蒙版自動變成 PowerPoint 原生物件。驗 zip 內實際順序、關鍵文字、文字框、圖形、圖片；有可用的簡報 renderer 時重開渲染，另驗字型和樣式。缺可編輯文字可保留已驗證的 PDF，PPTX 不能宣告成功。
4. 要固定外觀：`pptx: "raster"` 整頁嵌圖，明確標「圖像型 PPTX」；文字不可在其中編輯或搜尋。若兩者皆要，分別驗 HTML/PDF 外觀與原生 PPTX。LibreOffice 渲染證明相容路徑，不等於 PowerPoint 或 Keynote 實機驗收。

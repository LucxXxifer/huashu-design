# 動態與音訊

做三張真實渲染的方向板，選定後寫分鏡：每鏡說／看什麼、留多久、怎麼切、動作與聲音對應哪個 cue。保留可重播 HTML 與最終影音；固定比例、首尾、轉場、字幕安全區和節奏分別打磨。可沿用上游 `animations.jsx`（Stage / Sprite）、`narration_stage.jsx`、SFX 庫與導演稿；React 等資源要放專案本地。非必要的水印、固定鏡頭數、指定傾角和音效配額按內容裁定。

| 路線 | 先決定什麼 |
|---|---|
| 不需旁白 | 看畫面能不能懂；適當音樂、事件 SFX 或明確無聲。若素材必要，缺檔須擋。 |
| 短片有旁白 | 簡單段落可先剪畫面再加實測音訊；若承諾逐詞、卡點、逐 cue，就用長解說的對齊工序。時長短不代表可以省旁白。 |
| 長解說／精準對齊 | 先審講稿與供應商，取實際音訊和時間資料，再鎖鏡頭和 cue。音檔錯序、重疊、缺段、音長不符都不能硬截。 |

用使用者實際錄音或明確同意的配音方式。未獲使用者同意的 macOS `say` 只供有標籤的本機試音；它不自動滿足指定聲線、語言、逐詞時間戳或授權。付費服務記提供方、會傳的資料、費用和原樣輸出；以文字、聲線、參數和區段 hash 做快取。僅重試明確未受理的暫時錯誤；結果不明先查作業狀態，防止二次生成或計費。播放 HTML 和混音 MP4 都要驗；技術掃描識別非靜音，不判聲音內容、角色和混音品質。

使用 [video](runtime.md#video) 時，載入前設 `window.__seekRender`／`__recording`；就緒後由 `window.__seek(t)`（秒）同步或 Promise 地更新畫面，seek 模式凍結自驅時鐘。只渲染顯式舞台，不靠啟發式靜默隱藏版面。兩次同時間取樣像素一致只證明抽樣；CSS 自驅、亂數、直播或不受 seek 控制的動畫需改成可控方案。認真需要更完整合成引擎時讀上游 HyperFrames 路線；先核對它的 runtime、資料流和現成資源，避免自動安裝。

用 ffprobe 驗成品尺寸、幀數、音軌、時長；用獨立解碼抽起始、轉場、尾幀和 cue，亦查不預期的黑畫面。聽混音與字幕；若刻意全黑，本版會標失敗，人工核對並在專案記錄中另驗。GIF 由已驗 MP4 另出、再驗尺寸與時序，例如 `ffmpeg -n -i video.mp4 -vf "fps=12,scale=720:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" preview.gif`；GIF 無聲。
